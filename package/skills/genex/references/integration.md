# Deliver an asset that the game actually uses

Tool results include `jobId`, `model`, `task`, `files`, `assets`, measured time and a worker receipt. `files` are exact project-relative paths. Browser `assets` entries supply their exact `url`, already stripped of a host-selected `public/` prefix when applicable. Copy these strings verbatim into one asset map; never reconstruct a UUID. Unity files have `url:null`. Do not use private plugin paths or copy model weights into the game.

Genex owns registration: `assets.deliver` records delivery, refreshes Assets and records the build location. Files generated in a build worktree belong to that build until landing. A stopped build may leave originals retained but absent from the game folder. Use `theastraydev-local-models__assets` to find this game's jobs and `theastraydev-local-models__retrieve` to restore their bytes into the current workspace. Retrieval refuses to overwrite changed files and never runs inference. The setup panel also offers Restore assets for the currently open game.

Use the project's asset convention. An import-managed file under `src/` may be bundled by Vite; a file under `public/` is served relative to that directory and is not imported with a `/public/` URL. Files returned under top-level `assets/` are not automatically public in every framework: copy only the needed output into a new path in the configured public root or import it through the established bundler. Preserve originals and existing user files. Check build output includes dependencies and assets.

Three.js: use the project's existing `TextureLoader` and `GLTFLoader` imports and matching renderer version. Apply the correct base-color color space supported by that version; do not mix renderer distributions or download another three.js. Inspect the mesh's forward/up axes and align them with gameplay before centering, fitting its bounds and placing its bottom on the floor. A vehicle can load successfully while still facing sideways. Choose camera and lights that show the actual object. A static mesh can move as a whole through gameplay code but has no generated skeletal animation. Dispose unused resources; reuse geometry/materials for repeated props.

Audio: load the returned WAV with the game's existing audio system, start audio after a user gesture, set conservative gains, and test the actual gameplay event. Report whether you listened or only checked waveform, duration and loading. For music crossfades avoid stacking a new audio instance every loop or retry.

Validate in the preview and in the production build when available: no missing asset requests, model visible at a useful size, control loop working, sound attached to its intended event. A passed generation receipt proves file production and delivery, not a playable game. Reuse an existing job with `theastraydev-local-models__retrieve` instead of generating the same asset twice.

## Required runtime use check

The template `loadAsset(name)` accepts only short root slugs, not `assets/theastraydev-local-models/<job>/model.glb`. For a delivered GLB use the matching Three.js `GLTFLoader.loadAsync` and the exact returned URL. If the game has `loadGeneratedAssets`, return the loaded scene from it and pass that scene into the actual player entity. Calling a loader and then passing `carModel: null` still uses a placeholder. Generate, integrate and inspect one required asset before starting optional polish.

Call `theastraydev-local-models__inspect-use {"id":"<exact jobId>"}` after wiring. This is the same host runtime observation used by Genex Tools. If `ok:false`, fix missing loads or inaudible playback and repeat the inspection. A successful visual load is only `integrated`: inspect the attached image, then call `theastraydev-local-models__verify-use` with the exact `id`, `inspectionId` and a concrete `note`. Audio is verified only from advancing playback with non-silent output. Verification is scoped to this workspace; another build needs its own inspection. Never report the requested asset category as done while it remains unconfirmed.
